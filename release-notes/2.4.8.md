# SphereDex 2.4.8 release notes

This candidate is fresh code for the 2.4.8 train. It is not a resubmission of the binary already in App Store Connect. Android versionName and the in app version are 2.4.8. Android versionCode stays at the local fallback of 21. The Play bundle workflow, which is manual, sets the upload code to 100 plus the GitHub run number. This branch does not run that workflow.

iOS marketing version stays 2.4.8. The repo build number stays 29, in project.yml and the generated project. ci_post_clone.sh only regenerates the Xcode project. It does not set a store build number. The signed in App Store Connect log for the Archive and Upload workflow on main, commit fc4ba783b8112ea7b79aba1cc12e17904ae2b645, says it prepared version 2.4.8, build 413. The uploaded metadata bundle version string is 413. That workflow had no environment variable and no build number written into the archive invocation. Apple's Xcode Cloud document, Setting the next build number for Xcode Cloud builds, says Xcode Cloud assigns an integer and increases it with each build, and App Store Connect uses that Cloud build number. The next number is changed in the app's Xcode Cloud settings, on the Build Number tab, not by a workflow environment variable. The signed in page did not show the next counter, so this note does not pick 414. Build 413 is not reused. The one allowed archive should take whatever integer Xcode Cloud assigns when that archive runs.

## App Store: What's New in This Version

SphereDex 2.4.8.

• Print your collection from Export. The report is grouped by set and includes serials, graded slabs and sealed product, with the date and a total. A second report leaves prices out.
• Give an owned card a place name, such as Binder 2, page 5. Find my cards lists them grouped by place.
• Share your wants and your spares as a link. Nothing is added to the other person's collection. Prices stay off unless you choose to include them.
• Closest winning decks ranks official event decks by how close your collection is. Importing one makes a new deck.
• Mark a deck as Built so its copies stay with that deck. Other decks only count the copies that are still free.
• Send a raw copy to be graded. It stays in your count while it is away. When it returns you log the grade and it becomes a slab.
• Each set shows the live and sold value of the cards you own, including graded copies.
• The deck builder can show only cards you own. The scanner knows the gold Jetragon Soul.
• Daily Pal guess on Rewards: one hidden card a day, clues after a miss, streak kept on this device.
• Wishlist cards can be tagged Must have, Want, or Someday, with a buy at or under price and an optional monthly budget.
• The English Eternal Ascent booster is 30 Jan 2027. Trial decks TD03 and TD04 stay 18 Dec 2026.

Card names and art are used with credit to Pocketpair and Bushiroad. SphereDex is a fan made tracker and is not an official app.

## Not in this build

These were reviewed and left out on purpose.

• Android home screen widget. A debug build with the widget compiled, and it installed on a software emulator. The emulator system process then stopped responding, so the widget could not be placed or updated on the home screen. Hardware acceleration is not available here, and no cloud device run was used. It is not in this candidate.
• CompSniper as a price source. No credit and no privacy change for it is in this candidate. The optional token is not set, so the app does not say CompSniper is serving prices.
• Prices copied from another marketplace. The app can label such a row as an estimate instead of a sale, but that fill is switched off. This release does not add that coverage.
• The one off eBay sold backfill tool. It is not on main. It writes sold history through the operator tools, and the launch window it was written for has already aged out of eBay sold search. It was not added and it was not run.
• Set values under the set tiles. That view is already on main. The older patch was not merged over it.
• Zoe accessory and event bundle. No retail date was invented.

The backend release candidate is 3645874cf59757e698cadb0c37d95051ea4417ad. It is not merged and not deployed, and its tests and reviews for that head are still pending. It stores an announcement clock even when the post states no street day. That clock does not freeze a set that still has no day, so a later post with the same instant can fill the day. Once a day is stated, the same instant cannot move it. This app follows those rules for products, set days, and logos. Do not merge this pull request until that backend is deployed. The dates baked into the app are already 30 Jan 2027 and 18 Dec 2026.
